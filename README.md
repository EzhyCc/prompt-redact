# Prompt Redact · 提示词脱敏

> **在提示词发给 AI 之前，于本地把规则覆盖到的敏感信息替换为占位符。**
> 只出不回：它替你挡住原件，不替你还原结果。

`提示词脱敏` · `提示词安全` · `AI 隐私保护` · `本地脱敏` · `敏感信息替换` · `prompt redaction`

适用场景：把合同、报价单、日志、客户名单、代码片段粘进 ChatGPT / DeepSeek / Kimi / 豆包之前，
先把手机号、身份证、银行卡、API Key、私钥、数据库连接串换掉。数据不出本机，零依赖，不联网。

## 一眼看懂它在干什么

```text
输入：请联系张三，电话 138-0013-8000，身份证 110101199003071233
输出：请联系张三，电话 [手机号]，身份证 [身份证]
```

发出去的是下面那行。你屏幕上看到的、原始文件里的，都没有离开这台机器。

## 一句话诚实声明

本工具**不保证**识别所有隐私信息，**也不拦截**你绕过它的发送行为。
它只对规则覆盖到的、格式明确的敏感信息生效。
「已保护」只代表「命中规则的部分已被替换」，**不代表「这段内容安全」**。

## 它不做什么

这些问题都有人问过，答案是统一的"不做"：

| 不做 | 原因 |
|---|---|
| 自动还原 | 还原要把真实姓名手机号写进第三方页面的 DOM，等于把明文塞回最不该出现的地方 |
| 浏览器扩展 / 剪贴板钩子 | 尚未实现，见宿主矩阵 |
| 语义模型 / NER | 只做规则 + 校验算法，保证可解释、可离线、零依赖 |
| 账号体系 / 云端服务 / 统计上报 | 不收集任何数据 |
| 意图判断（区分查询型和生成型提示词） | 规则覆盖的格式类字段，在任何提示词里都该删，判断没有收益 |

## 快速开始

需要 Node.js 20 或更高版本。**零依赖，不需要 `npm install`。**

```bash
node test/selftest.js                              # 全部自测
node demo.js                                       # 看一段真实的前后对比
node tools/cli.js redact "电话 13800138000"        # 命令行脱敏
node tools/cli.js scan "邮箱 a@b.com"              # 只看命中，不输出替换结果
node tools/cli.js redact "联系人 张三" --add 张三   # 追加个人词表
node tools/serve.js                                # 启动规则调试器
```

### 规则调试器

```bash
node tools/serve.js            # 只监听 127.0.0.1:5173
```

浏览器打开 <http://127.0.0.1:5173/>，左边粘文本，右边立刻看到"会发给 AI 的东西"长什么样：

- 原文里将被替换的片段会高亮，鼠标悬停显示是哪条规则命中的
- 命中表列出 `ruleId / 类别 / 严重度 / token / 原文坐标`
- 打开「显示被丢弃的命中」，能看到因重叠而被更长规则覆盖的那些
- 发现漏检时，在「漏检申诉」里填那段文字，一键生成可直接加进规则库的 JSON

页面纯静态、零依赖，所有处理都在浏览器本地完成，不发任何网络请求。**必须通过 `serve.js` 访问**，直接双击 HTML 会因为跨源限制读不到规则文件。

### Word 文档：保格式脱敏与保格式填充

`.docx` 不能只抽成文本——交付物必须是 Word。两条命令，**只产出两个文件**：

```bash
# 1. 就地脱敏（格式不动），产出「-脱敏.docx」和「.map.json」
node tools/docx.mjs redact \
  --in "模板.docx" --out "输出目录" \
  --terms "某某科技=客户,某某医院=医院" --org

# 2. 在脱敏模板上重建各章正文（模型给出内容 JSON）
node tools/docx.mjs compose \
  --base "输出目录/模板-脱敏.docx" \
  --content "内容.json" \
  --out "成品.docx"
```

产出：

```
输出目录/
├── 模板-脱敏.docx     ← 给模型看的模板：占位符 + 原格式
└── 模板.map.json      ← 占位符 → 真实值（只留本地）
成品.docx              ← 交付物，格式继承模板
```

`内容.json` 结构：

```json
{ "项目简介": ["第一段", "第二段"], "初验目的": ["…"] }
```

章节名按「去掉编号和空格」比对，所以 `1 项目简介` 和 `项目简介` 都能匹配。

**实现要点**：段落级匹配、run 级落笔。Word 会把一句话拆进多个 run（`某大学` + `某医院`），只按 run 替换跨不过边界；所以按段落拼起来脱敏，改动后写进第一个 run。段落样式、自动编号、页眉页脚、表格全保留；代价是同段落内的混排格式会被合并。

**零依赖，不需要 Python、不需要 Office。** docx 的读写是自己实现的：ZIP 读写 + 一个只管 Office 文档的 XML 扫描器（按标签栈定位元素，能正确处理文本框里的嵌套段落）。

### 装完插件就能处理 Word

插件会把两个工具注册给模型，用户直接说「把 D:\合同.docx 脱敏」就行：

| 工具 | 作用 |
|---|---|
| `redact_docx` | 就地脱敏一份 Word，产出 `<原名>-脱敏.docx` 和 `<原名>.map.json` |
| `compose_docx` | 在脱敏模板上重建各章正文，产出成品 |

宿主没有 tools 能力、或 `@deepseek-ai/dsh-tools` 不可用时自动跳过，不影响聊天脱敏。

### 目录脱敏：把一整个资料夹交给 AI

单个文件不够用，真实场景是一整个目录：

```bash
node tools/redact-dir.mjs \
  --from "D:\项目\某医院\归档材料" \
  --to   "D:\项目\某医院\_redacted\材料" \
  --add  "某某科技=客户,某某医院=医院,张三=项目经理"
```

产出两份东西：

```
_redacted\材料\          ← 交给模型：全是 f001.txt 这种中性文件名 + 占位符
_redacted\材料.map.json  ← 只留本地：原始文件名、原值映射
```

模型基于 `_redacted` 干活，产出新文档后，本地回填：

```bash
node tools/redact-dir.mjs --fill \
  --map "D:\项目\某医院\_redacted\材料.map.json" \
  --from "D:\项目\某医院\_redacted\产出" \
  --to   "D:\项目\某医院\成稿"
```

**支持的格式**：

| 直接读文本 | 抽取文本（纯 Node 内置模块，不需要装 Office） | 明确不支持 |
|---|---|---|
| `.txt .md .csv .json .log .html .xml .yml .sql .js .py .ini .conf` | `.docx .xlsx .pptx` | `.doc .xls .ppt .pdf .zip` 等 |

不支持的会**逐个列出来**，不会假装处理过。

### 词表的两种写法

```json
"customTerms": ["张三", "某某科技"]
```
→ 占位符统一是 `[自定义词]`、`[自定义词_2]`

```json
"customTerms": { "某某科技": "客户", "某某医院": "医院", "张三": "项目经理" }
```
→ 占位符是 `[客户]`、`[医院]`、`[项目经理]`

**正式文档里用命名写法**。`甲方：[客户][医院]` 能读懂也能回填，`甲方：[自定义词_4][自定义词]` 不行。

### 命令行参数

| 参数 | 作用 |
|---|---|
| `--semantic` | 启用语义类规则（如公司名）。默认关闭，见"已知限制" |
| `--add 张三,李四` | 追加个人词表，逗号分隔，整词匹配 |
| `--json` | 输出完整的 `redact()` 返回值结构 |
| `--quiet` | 只输出结果，不输出统计 |
| `-f 文件路径` | 从文件读入而不是从参数读 |

退出码：`0` 正常、`2` 检测到高危残留（`blocked`，便于管道和 CI 使用）、`1` 参数错误。

## 规则与贡献

### 提交前必读：仓库里不许有真实数据

**示例、测试样本、文档、提交信息，一律只用虚构数据。**

| 用 | 不要用 |
|---|---|
| `某某科技`、`某某医院`、`张三`、`13800138000` | 真实客户名、真实项目名、真实人名 |
| `D:\项目\某某医院\归档材料` | 你本机的真实路径 |

真实数据只能出现在本机临时目录（`%TEMP%`）。一旦进了 git 历史，**只在最新提交里删掉是不够的**——旧提交依然可以按 SHA 访问，必须改写历史并强推，甚至删库重建。

这不是洁癖：这个工具的存在意义就是不让真实数据外流，它的仓库自己先得守住这条线。

规则由三层组成：**规则文件 → match 条目 → 校验器**。

一条完整可用的规则长这样（这条是真的能跑通的，照抄不会错）：

```json
{
  "id": "cn-mobile",
  "label": "手机号",
  "category": "contact",
  "tier": "format",
  "severity": "high",
  "token": "PHONE",
  "match": [
    { "type": "regex", "pattern": "(?<![0-9])1[3-9][0-9][- ]?[0-9]{4}[- ]?[0-9]{4}(?![0-9])", "validate": "cnMobile" }
  ],
  "note": "11 位大陆手机号；可能误报恰好以 1[3-9] 开头的长编号，靠前后断言收窄。"
}
```

字段说明：

- `tier`：`format`（默认启用）或 `semantic`（默认关闭，需用户手动开）
- `severity`：`high` 参与二次扫描阻断判定
- `token`：2–12 位大写字母，最终生成 `[TOKEN_4位十六进制]`
- `match[].validate`：可选，只允许 `cnMobile` / `cnIdCard` / `cnUscc` / `luhn` / `ipv4`
- `match[].valueGroup`：可选，`>0` 时只替换该捕获组（用于 `密码：xxx` 这类关键词锚定规则）

### 提一条规则的完整流程

1. 在 `rules/zh-CN/` 下对应文件里加一条 JSON（照上面的模板）
2. 在 `test/rule-samples.json` 里给它加 **2 个正例 + 2 个负例**
3. 跑 `node test/selftest.js`，必须全绿
4. 开 `node tools/serve.js`，在调试器里粘几段真实场景的文本，确认没有离谱误报
5. 提 PR，说明这条规则的目标场景和已知误报

正则书写硬约束（不遵守会在自测里被拦下）：用 `[0-9]` 不用 `\d`；用 `[.]` 不用 `\.`；所有量词必须有上限；禁止嵌套量词。

## 安全模型

- 占位符是可读的中文语义标签：`[手机号]`、`[身份证]`、`[报价总额]`；同类多值递增为 `[手机号_2]`
- 同一会话内，同一个值复用同一个 token（多轮对话里 AI 才能认为"还是同一个人"）
- 映射只存在内存 `Session` 里，进程结束即消失，**不落盘、不加密、不持久化**
- `redact()` 的返回值里**不含任何原文**：只有 token、规则 id、原文坐标
- core 不依赖任何宿主 API，同一份代码可跑在 Node 与浏览器

## 已知限制

这些不是 bug，是设计取舍，写出来是为了让你决定要不要用它：

- **不识别中文人名、公司名、项目代号**。靠个人词表（`--add`）补。中文人名靠通用规则必然误报，维护一个 3000 字词典不如让你自己填 10 个词。
- **语义类规则默认关闭**。打开后"帮我分析深圳市××科技有限公司的供应链风险"里的公司名也会被换掉，需求直接失效。
- **单会话映射上限 500 条**，超出整体清空。超长会话会重置 token，AI 侧的多轮一致性会断。
- **二次扫描是保险丝**，正常路径下不会触发，它防的是"某条规则命中了自己产出的 token"。
- **覆盖率不等于安全性**。没接入的通道（桌面客户端、移动端）完全不受保护。
- **上传文件的文件名和本地路径会明文随请求外发**。插件拿到的是 file 块，投影成 handle 文本发生在本插件之后，兜不住。上传前先重命名。
- **工具结果默认不脱敏**。模型读文件、跑命令的返回内容默认原样进入上下文；需要时开 `redactToolResults`。

## 在 DeepSeek Harness 里用

DSH 的插件页 →「添加插件」→「安装第三方插件」→ 粘这个地址：

```
https://github.com/EzhyCc/prompt-redact/archive/refs/heads/main.tar.gz
```

或者手动放：把仓库克隆到 `~/.dsh/plugins/prompt-redact`，重启 DSH。

**它挂在哪**：cordis 的 `llm/stream` 瀑布。DSH 每发一次模型请求都会派发这个事件，插件在这里把 `role: "user"` 的文本块替换后再放行。

**配置**（`cordis.patch.yml`，也可以在插件配置界面改）：

| 项 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 总开关。关掉后完全透传，不改任何字节 |
| `enableSemantic` | `false` | 语义类规则（公司名）。开了会把"分析××公司的风险"里的公司名也换掉 |
| `customTerms` | `[]` | 个人词表，整词匹配，填人名、客户名、项目代号 |
| `redactToolResults` | `false` | 连工具结果一起脱敏。**上传文件的内容要靠它**，见下 |
| `redactSessionLog` | `false` | 把脱敏点前移到「消息写入会话记录之前」，聊天界面里自己那条消息也显示占位符 |
| `maxTextLength` | `200000` | 单块文本超过这个字符数就跳过脱敏，避免卡住对话 |
| `maxEntries` | `500` | 映射上限，超出整体清空 |

### `redactSessionLog`：让界面也显示占位符

默认只改出网请求，所以**聊天界面里你自己那条消息仍是原文**（DSH 把原文写进 append-only 会话日志，界面读的是日志）。

打开这个开关后，插件会包一层 `session.append`，在 `user/message` 落盘之前完成替换。效果：

| | 默认 | 开了 `redactSessionLog` |
|---|---|---|
| 发给 AI 的 | 占位符 | 占位符 |
| 界面里自己那条消息 | 原文 | 占位符 |
| 会话日志里存的 | 原文 | 占位符 |

**代价**：日志里不再有原文，你自己的历史消息就永久读不了了。想要原文就先用 `prompt-redact redact --save-map` 把映射存下来，之后 `fill` 回去。

**风险**：这是对宿主内部的侵入（包装 `append`）。包装失败会静默跳过并在日志留警告，不影响对话，但气泡还是原文。

### 配置放在哪

**配置属于产品，不属于宿主。** 配置文件是一个，所有适配器共读：

```
~/.prompt-redact/config.json        ← 默认位置
$PROMPT_REDACT_CONFIG               ← 环境变量可覆盖（自定义部署 / 测试）
```

`cordis.patch.yml` 里的值是默认值，配置文件里的键覆盖它。改完需要重启宿主（或重载插件）才生效。设置页（`node tools/serve.js`）写的就是这个文件。

> 为什么不做 DSH 内置的设置页：那需要往 DSH 的 React 插槽里注册一个客户端组件，得为它维护一整套构建管线，而这份工作只服务 DSH 一个宿主——浏览器扩展、本地代理、PWA 一个都用不上。配置和 UI 跟着产品走，宿主只负责读同一个文件。

### 宿主接入契约

接一个新宿主只需要三步，这也是这个项目能被多个 AI 产品复用的原因：

1. 引入 `src/index.js` 的 `redact()`（纯 ESM，无 IO，Node 和浏览器都能跑）
2. 从 `~/.prompt-redact/config.json` 读 `enabled` / `enableSemantic` / `customTerms` / `redactToolResults`
3. 在数据离开设备之前调用它，把 `role: user` 的文本块换掉

宿主自己的框架、语言、协议都不影响这三步。

### 出错时会发生什么（这一段是说给要装它的人看的）

插件是插在对话链路中间的一段代码，它出错不能让你发不出消息。所以：

| 情况 | 行为 |
|---|---|
| 规则文件读不到 / JSON 坏了 | 插件退化为不生效，日志留一条警告，对话照常 |
| 脱敏过程抛异常 | 该请求按原文放行，日志留一条 `脱敏失败` |
| 某块文本超过 `maxTextLength` | 这一块跳过，不脱敏，也不报错 |
| 插件的判断逻辑本身崩了 | 兜底 catch 放行 |
| `enabled: false` | 一个字节都不改 |

代价是**失败时是静默降级**（只写日志）。因为插件没有界面，"显示已保护但实际发了原文"这种情况不会发生——它没有地方显示"已保护"。

### 上传的文件怎么处理

DSH 里上传的文件**不会**作为正文随你的消息发出。它会被投影成一段 handle 文本：

```
[File "客户合同.pdf" (102400 bytes, sha256:1a2b3c4d): verbatim read-only copy saved at
"C:\Users\...\客户合同.pdf". Read that path with your file tools...]
```

模型拿到的是**文件名 + 本地只读路径**，要读内容必须调文件工具——文件正文是以 `role: "tool"` 的消息回到上下文的。

所以：

| | 默认 | `redactToolResults: true` |
|---|---|---|
| 文件名 / 路径 | ❌ 明文外发 | ❌ 仍然明文（投影发生在本插件之后） |
| 文件正文（模型读出来的部分） | ❌ 明文进上下文 | ✅ 会被替换 |
| 你自己打的字 | ✅ 脱敏 | ✅ 脱敏 |

**打开 `redactToolResults` 的代价**：模型读到的代码、日志、配置也会被改写。如果它正在修一个文件里写死的电话号码，可能把该改的地方也换成了 token。所以默认关闭，只在你主要拿它处理文档（合同、报价单、验收材料）时打开。

文件名本身可能就带敏感信息（`客户合同-某某科技.pdf`），这条插件兜不住——上传前先重命名。

**怎么确认它真的生效了**：发一句「我手机 13800138000，帮我记一下」，然后看会话日志或请求体——里面应该是 `[手机号]`，不是原号。

> ⚠️ 只处理 `role: "user"` 的 text 块。system 提示词、已有 assistant 回复、图片和文件引用一律不动。
> 脱敏过程抛异常时会**放行并把警告写进日志**，不会阻断你的对话——这是取舍，不是承诺。
